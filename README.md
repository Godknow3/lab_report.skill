# Lab Report 实验报告工作流

`lab-report` 是一个面向高校课程实验报告的个人 Codex Skill。它根据实验要求、报告模板、课程资料、实际代码、输入素材和真实输出，制作、填写、修改或审查 Word 实验报告。

它重点解决以下问题：

- 报告内容与代码、参数或结果不一致；
- 实验现象分析空泛，只有“效果良好”等结论；
- AI 生成内容模板化、重复或过度拔高；
- 图片堆放、拉伸、过小、图注缺失或分页混乱；
- Word 内容完成后没有经过实际渲染检查。

## 安装位置

```text
C:\Users\xxx\.codex\skills\lab-report
```

目录结构：

```text
lab-report/
├─ SKILL.md
├─ README.md
├─ agents/
│  └─ openai.yaml
└─ references/
   ├─ evidence-and-audit.md
   ├─ word-figure-layout.md
   └─ writing-style.md
```

其中：

- `SKILL.md`：Agent 执行任务时遵循的核心工作流；
- `evidence-and-audit.md`：实验事实映射和最终核查规则；
- `word-figure-layout.md`：Word 图片比较、图注、分页和渲染检查规范；
- `writing-style.md`：降低模板化 AI 表达的写作规范；
- `openai.yaml`：Codex 界面中的显示名称和默认提示词。

`README.md` 仅供使用者阅读，不是 Agent 的执行指令。

## 基本用法

在 Codex 新任务中显式调用：

```text
使用 $lab-report 完成本次实验报告。
```

为了获得稳定结果，建议同时提供四类材料：

```text
实验要求：
报告模板：
课程资料：
代码与结果目录：
```

完整提示词示例：

```text
使用 $lab-report 完成本次课程实验报告。

实验要求：
D:\课程\实验要求.doc

报告模板：
D:\课程\实验报告模板.docx

课程资料：
D:\课程\课件.pdf

代码与结果目录：
D:\项目\experiment

要求：
1. 先核对实验任务、代码、参数、输入素材和实际输出；
2. 建立报告内容与实验事实的对应关系；
3. 直接填写原 Word 模板，不重新设计报告结构；
4. 代码部分只保留体现算法流程的关键代码；
5. 实验结果分析必须对应真实结果，不得虚构现象；
6. 合理安排比较图片、图号、图注和分页；
7. 使用自然的本科实验报告语言；
8. 完成后渲染完整 Word，逐页检查并修正版式；
9. 输出可直接提交的 docx 文件。
```

## 工作流程

Skill 默认按以下顺序处理完整实验报告：

```text
读取实验要求与模板
        ↓
核对课程理论、代码和参数
        ↓
运行或验证实验结果
        ↓
建立要求—代码—参数—结果证据映射
        ↓
按原模板分任务填写报告
        ↓
插入和编排真实结果图片
        ↓
自然化技术表达
        ↓
渲染 Word 并逐页检查
        ↓
交付可提交文档
```

核心原则是：先固定实验事实，再撰写和润色报告。

## 常用调用方式

### 制作完整报告

```text
使用 $lab-report，根据实验要求、课程课件、项目代码和真实结果，填写现有 Word 实验报告模板。完成后进行内容核查和全页渲染检查。
```

### 审查已有报告

```text
使用 $lab-report 审查这份实验报告。检查任务是否完整，代码、参数、结果图和分析是否一致，并检查图片排版与 Word 分页。先列出问题，不要直接修改。
```

### 修改已有报告

```text
使用 $lab-report 修改这份实验报告。保留原模板，只修正技术错误、空泛分析、图片排版和明显的模板化 AI 表达。
```

### 只降低 AI 味

```text
使用 $lab-report 对报告进行自然化修改。保留公式、代码、参数和实验事实，不得虚构实验过程或个人经历。
```

### 补充结果与分析

```text
使用 $lab-report 根据项目 output 目录中的真实结果补充“实验结果与分析”，将对应图片插入 Word 的正确位置，并说明操作、现象和原因。
```

### 只检查图片排版

```text
使用 $lab-report 检查这份 Word 实验报告的图片排版。重点检查清晰度、宽高比、比较尺度、图号、图注、正文引用、跨页和空白区域，并直接修正后重新渲染验证。
```

## 图片排版规则

Skill 会根据比较目的选择布局：

- 单张关键结果居中显示；
- 原图与结果图优先双栏比较；
- 三至四张紧密相关的结果可采用 `2×2` 网格；
- 包含细节或文字的图片每行不超过两张；
- 并排比较图尽量保持相同显示尺度；
- 图片保持原始宽高比，不强制拉伸；
- 图片和图注保持在同一页；
- 比较图组不跨页拆分；
- 每张图都应在正文中被引用和分析；
- 最终必须将 DOCX 渲染为页面图片并逐页检查。

## 材料组织建议

推荐实验项目结构：

```text
experiment/
├─ input/          原始图片、视频或数据
├─ output/         实际运行得到的结果
├─ src/            实验代码，可选
├─ experiment.py   主程序示例
├─ README.md       运行方式和依赖说明
└─ requirements.txt
```

报告任务开始前，应删除无关的旧输出或明确哪些文件属于最终版本，避免 Agent 将过时结果写入报告。

该 Skill 适用于：

- 数字图像处理；
- 数字信号处理；
- 程序设计；
- 机器学习；

## 常见问题

### 输入 `$lab-report` 后没有出现技能

重新启动 Codex 或新建任务，再输入 `$lab-report`。显式调用比依赖自动触发更稳定。

### 报告内容正确，但图片布局不好

继续发送：

```text
使用 $lab-report 重新检查 Word 图片排版，渲染所有页面并修正图片尺寸、比较布局、图注和分页。
```

### AI 味仍然明显

要求进行单独的语言审查，不要重新生成整篇报告：

```text
使用 $lab-report 只进行自然化修改，删除空泛套话和重复总结，保留全部技术事实、公式、参数和图号。
```

### 代码和报告结果不一致

要求重新建立证据映射：

```text
使用 $lab-report 重新核对代码、参数和 output 文件，列出所有不一致之处，确认后再修改报告。
```

## 维护建议

使用两三次后，根据实际失败案例进行小范围更新。优先修复可重复出现的问题，不要把每次实验的具体内容都写入通用 Skill。

如需修改 Skill，可以直接提出：

```text
使用 $skill-creator 更新 $lab-report，增加……规则。
```
